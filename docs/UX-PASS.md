## Workarounds to discuss (U5–U9)

For each: what the author has to do today, what a helper would be, and what speaks against it.

**U5: a conversation that continues another counts as unreachable.**
- *Today:* `reachable()` in `src/shared/quest.ts` walks only one quest's own edges from its Start node.
  When conversation A ends in a Link › trigger whose rule lands on a node of conversation B (Heliopolis:
  the "won" conversations after the vault battles), every node of B after that point is "can't be
  reached from the start". Heliopolis silences each one with an ignore (`saga.ts`, one per node).
- *Helper:* the check also starts from every node that another quest's Link › trigger can land on
  (matched by trigger, the same way the export writes the rules). Editor only; nothing exported changes.
- *Against:* matching a trigger to its rules can be ambiguous (the conditions decide at runtime), so the
  check would treat "might land here" as reachable. A mistake could then hide behind a link that never
  fires. With U3 (the Fight node), Heliopolis's case disappears anyway: Won is a normal edge.
- *Suggestion:* do it, as "reachable from another conversation" (an info line, not silence), after U3.

**U6: Back replays a long scene.**
- *Today:* an option that returns to a Dialog node shows its whole text again. Heliopolis's `scene()`
  helper splits every such scene by hand into two nodes: the full text with one "go on" option, then a
  short hub node with the real options that the questions link back to.
- *Helper:* a Dialog node field "When you come back" (short text). Export: the node's rule gets a
  second, higher-scored copy that shows the short text when `$<quest>_<node>_seen` is set (the first
  visit sets it). Vanilla does the same with its "seen" flags, e.g. `$askedCommission`.
- *Against:* one more rule per such node, and a flag per node in the save (per conversation `= true 0`
  would avoid it when "come back" only means within one visit). Authors who want a different set of
  options on return still need two nodes.
- *Suggestion:* do it; default scope "within this visit" (no saved flag), "ever" as a choice.

**U7: no way to just close the dialog.**
- *Today:* a fleet's comm link that ends with "they leave" (Heliopolis act 1, the Vanguard example) needs
  a raw script line `EndConversation` on the last Dialog node. Link › "back to the menu" returns to the
  fleet's interaction menu (Attack / Leave …) and only closes the dialog where there is no menu.
- *Helper:* a fourth Link mode, "close the dialog" (`EndConversation`), for comm links, fleets that
  leave, and scenes that should end the visit.
- *Against:* nothing found: it's a vanilla command, the engine and Play already handle it
  (`rules/engine.ts`). The only risk is authors using it at a market where they meant "back to the
  menu", so the Link node's help says when to use which.
- *Suggestion:* do it.

**U8: design notes can't be written into the mod.**
- *Today:* the write guard (`src/main/workspace.ts`, `WRITABLE_EXTS`) refuses `.md` files, so
  Heliopolis's build writes `sagaforge/design/*.md` itself.
- *Helper:* allow `.md` only under `<mod>/sagaforge/` (already left out of release zips).
- *Against:* Saga Forge has no Markdown editor page outside the Script tab, so today only a build
  script benefits; it widens the guard for little gain in the app itself.
- *Suggestion:* keep the guard as it is unless the app gets a "notes" feature; record the reason.

**U9: Play mode's plugin buttons are pseudo-options.**
- *Today:* a Plugin node's results show in Play as `__sf_plugin|…` options that the Play panel handles
  itself; Heliopolis's `play.ts` harness has to do the same.
- *Helper:* make them real options in the engine.
- *Against:* only scripts that drive the engine notice; for the app's users it already works, and the
  engine would need a fake "plugin result" rule set.
- *Suggestion:* keep, with that reason.
