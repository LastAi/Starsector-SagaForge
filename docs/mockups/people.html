Conditional text inside a Dialog node

In the Quest planner's text field, a phrase shows as a chip. For a one-off variation you don't want to name, type { and pick conditions inline; the editor turns it into an unnamed phrase for that node on export. The dialog preview's Test context gets switches for the conditions the text uses, and Show all variants draws every case side by side.

Dialog node "Debrief" · text
"$vgc_reyes_title." Reyes nods $vgc_reyes_mood. "Forty crew, home alive. { if commissioned with Vanguard: The Compact owes you a promotion, not just a payment. | else: The Compact pays its debts. }"
{ if pay == 2: She transfers the doubled fee without comment. }
Purple chips are named phrases (reusable, from the People page). Blue chips are inline variations, edited in place; an inline variation with no else shows nothing when no case matches.

Vanilla first. Vanilla's own tokens still work and are listed in the token picker: $PlayerSirOrMadam already uses the player's honorific, and $playerLastName, $faction, $marketName and the rest fill in as usual.
How it runs in game. SagaLib registers one token generator with the game's rules (RulesAPI.addTokenReplacementGenerator). When the game fills tokens in a line, it asks SagaLib for $vgc_… phrases, and SagaLib picks the first case whose conditions match.
Big differences stay as rules. When the conversation itself branches (different options, different next steps), use a Branch node: separate rules, picked by FireBest. Phrases are for wording, not for flow.
Without SagaLib. A dialog-only mod with no SagaLib can still use inline variations: the export splits the node into one rule per combination (up to 4). More than that needs SagaLib, and Problems says so.
